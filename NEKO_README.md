# LLM-Agnostic Web Conversion Template: Any Website to Next.js

**Model-agnostic AI workflow for converting any HTML-based website to Next.js + Tailwind CSS**

Use the AI model that fits your needs and budget to replicate any website's frontend. Premium options like Claude Sonnet deliver excellent results. Budget-friendly alternatives like DeepSeek or Qwen work just as well. Open-source models, GPT-4, or whatever's built into your coding environment - the template handles them all. Convert the static appearance (HTML structure and CSS styling) of any site to Next.js, without being locked into expensive subscriptions or specific providers.

## Overview

This template provides a page-by-page conversion workflow that **clones the static visual appearance** of any website to Next.js. Maintains 90%+ visual fidelity (HTML structure + CSS styling) while migrating to modern infrastructure.

**What gets converted:**
- ✅ HTML structure → React/JSX components
- ✅ CSS styling → Tailwind utility classes
- ✅ Static images, fonts, assets
- ✅ Page layouts and responsive design
- ✅ Navigation and links (preserved, not functional yet)

**What does NOT get converted:**
- ❌ Backend logic (PHP scripts, Python views, etc.)
- ❌ Database queries and data
- ❌ Authentication/authorization
- ❌ Form submission handlers
- ❌ API integrations

**Result:** Pixel-accurate Next.js frontend. Backend features require separate implementation using Next.js patterns (API routes, Server Components, etc.).

**LLM-Agnostic Design:**
- ✅ Claude (Opus, Sonnet, Haiku)
- ✅ GPT-4, GPT-4o, GPT-4o-mini
- ✅ Open models (DeepSeek, Qwen, GLM-4, Llama 3)
- ✅ AI coding tools (Cursor, Roocode, Windsurf, Cline, Google Antigravity)
- ✅ Future LLMs and coding assistants

**Universal HTML Source Support:**
- Static HTML files (.html)
- Server-rendered pages (PHP, Django, Rails, ASP.NET, Express)
- Static site generators (Jekyll, Hugo, Eleventy, Astro)
- CMS platforms (WordPress, Joomla, Drupal, Webflow)
- Archived or scraped websites

**Key Benefits:**
- **No vendor lock-in** - Works with any AI provider
- **Cost flexibility** - Use expensive or budget models as needed
- **Incremental migration** - Deploy page-by-page, not all-at-once
- **Production quality** - 90%+ visual resemblance maintained
- **CDN-ready** - Optimized for Vercel/Cloudflare/Netlify

## Quick Start

1. **Clone this repo** or copy instruction files to your project folder
2. **Create Next.js project in current directory**:
   ```bash
   # Navigate to your project folder first
   cd my-project
   
   # Create Next.js in current folder (note the . at the end)
   npx create-next-app@latest . --typescript --tailwind --app
   
   # This creates app/, public/, package.json in current directory
   # NOT in a subfolder
   ```
3. **Choose your instruction file**:
   - `CONVERSION_INSTRUCTION.md` - Comprehensive guide with detailed explanations
   - `CONVERSION_INSTRUCTION_LITE.md` - Streamlined workflow with step-by-step checklists
4. **Upload to AI assistant workspace** (Roocode/Cursor) or use via API
5. **Start converting** using prompts below

### Which Instruction File to Use?

**Use CONVERSION_INSTRUCTION.md (Full) when:**
- First time using this workflow (learning mode)
- Complex pages with forms, interactions, or dynamic content
- Working with Claude Sonnet, GPT-4, or other advanced models
- Need detailed explanations and context

**Use CONVERSION_INSTRUCTION_LITE.md when:**
- Already familiar with the workflow
- Converting simple static pages
- Using any AI model (optimized for clarity and consistency)
- Want faster execution with less token overhead
- Automating via API

Both files produce the same output quality - LITE is just more direct.

### Getting HTML from Your Source

The conversion works with **rendered HTML** - what the browser sees. Here's how to get it:

**Method 1: Browser (Universal)**
- Visit your page in browser
- Right-click → "View Page Source" or "Inspect" → Copy outerHTML
- Works for any live website

**Method 2: Save Complete Page**
- Browser → File → Save Page As → "Webpage, Complete"
- Gets HTML + all assets (images, CSS, JS)

**Method 3: Command Line**
```bash
# Download HTML
curl https://yoursite.com > page.html

# Or with assets
wget -p -k https://yoursite.com
```

**Method 4: From Files**
- PHP/Python/Rails: Run dev server, access via browser, use Method 1
- Static HTML: Open file directly in browser
- WordPress: View published page, not admin panel

You're converting the **output**, not the source code. Whether it was generated by PHP, Python, WordPress, or hand-written HTML doesn't matter.

## Automation with Claude API

For bulk conversions, you can automate the workflow programmatically:

```javascript
// Example: Automated page conversion via Claude API
const fs = require('fs').promises;

const convertPage = async (sourceUrl, targetPath, useLite = false) => {
  const instructionFile = useLite 
    ? 'CONVERSION_INSTRUCTION_LITE.md' 
    : 'CONVERSION_INSTRUCTION.md';
  const instruction = await fs.readFile(instructionFile, 'utf-8');
  
  const response = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-api-key': process.env.ANTHROPIC_API_KEY,
      'anthropic-version': '2023-06-01'
    },
    body: JSON.stringify({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 4000,
      messages: [{
        role: 'user',
        content: `${instruction}\n\nConvert ${sourceUrl} to ${targetPath} with Tailwind CSS`
      }]
    })
  });
  
  const result = await response.json();
  // Parse and save the generated code
  await fs.writeFile(targetPath, extractCode(result.content));
};

// Convert entire sitemap
const sitemap = [
  { url: 'https://oldsite.com/', path: 'app/page.tsx' },
  { url: 'https://oldsite.com/about', path: 'app/about/page.tsx' },
  { url: 'https://oldsite.com/services', path: 'app/services/page.tsx' }
];

for (const page of sitemap) {
  await convertPage(page.url, page.path, true); // Use LITE for efficiency
  await delay(1000); // Rate limiting
}
```

**Token efficiency:**
- **Full version**: ~6,000 instruction tokens + ~8,000 total per page
- **LITE version**: ~2,200 instruction tokens + ~6,000 total per page
- **Savings**: ~30% fewer tokens using LITE for simple pages

**Use cases for automation:**
- 50+ page conversions
- Consistent template-based pages
- Batch processing documentation sites
- CI/CD pipeline integration

**Manual is still recommended for:**
- Complex interactive pages
- Unique layouts requiring human review
- Quality assurance and visual verification

## Tips for Success

### 1. Start Simple
Convert your simplest static page first (usually About or Services page, not homepage). This lets you learn the workflow without complex navigation.

### 2. Visual Comparison is Critical
After each conversion:
- Deploy to Vercel preview
- Open original PHP and new Next.js side-by-side
- Check on mobile, tablet, desktop
- Fix discrepancies before moving to next page

### 3. Component Timing
Don't extract components too early. Convert 2-3 pages first to see what actually repeats. Premature extraction wastes time.

### 4. Defer Complexity
- Skip meta tags optimization initially
- Hardcode dynamic content temporarily
- Handle PHP database queries after all static pages done
- WAF migration is separate from conversion

### 5. Progressive Prompts
- **Pages 1-2:** Detailed prompts with all requirements
- **Pages 3-5:** Medium prompts referencing previous work
- **Pages 6+:** One-liner prompts once patterns established

### 6. Asset Organization
Create consistent paths early:
- `/public/images/` for all images
- `/public/fonts/` for fonts
- `/public/icons/` for icons/SVGs

Update all references immediately to avoid broken assets.

## Common Pitfalls

❌ **Converting all pages at once** → Convert one at a time, deploy and verify  
❌ **Ignoring asset paths** → They break silently, check every image/font  
❌ **Skipping visual comparison** → Issues compound if not caught early  
❌ **Over-engineering components** → Keep it simple, extract only what clearly repeats  
❌ **Fighting Tailwind** → Some complex CSS is fine in globals.css temporarily

## FAQ

**Q: Does this work with WordPress sites?**  
A: Yes. View the published page (not admin panel), save HTML, and convert. For dynamic WordPress features (blog posts, custom post types), you'll need to export content separately and create data sources.

**Q: Can I convert server-side rendered pages (Django/Rails/ASP.NET)?**  
A: Absolutely. The workflow converts the HTML output, not the backend code. You'll handle data fetching separately via Next.js API routes or Server Components.

**Q: What about single-page apps (React/Vue/Angular)?**  
A: Not ideal. Those are already modern. This template is for traditional multi-page sites with server-rendered HTML.

**Q: Can I automate this for 100+ pages?**  
A: Yes, using Claude API (see Automation section). But manually verify first 5-10 pages to establish quality patterns before bulk processing.

**Q: Do I need to know React deeply?**  
A: No. The AI handles JSX conversion. You just verify visual output and provide feedback.

**Q: How long does each page take?**  
A: First page: 30-60 min (learning). Subsequent pages: 10-20 min once patterns established. With API automation: ~2-5 min per page.

**Q: What about SEO and meta tags?**  
A: Defer until after conversion. Next.js makes it easy to add via Metadata API later.

**Q: Can I convert just the frontend and keep my existing backend?**  
A: Yes. Deploy Next.js frontend to Vercel/Cloudflare, keep your PHP/Python/Rails backend as API, connect via fetch calls.
